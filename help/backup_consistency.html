Prepare running machines

Use QEMU Guest Agent keeps the machine running and requires a responding agent inside it. Cloudmin briefly freezes its filesystems, takes a temporary snapshot, then thaws them. For file disks, new writes go to temporary overlays while Cloudmin copies the original disks. It then merges those writes back. For LVM disks, Cloudmin briefly pauses the guest to create native snapshots. Writes stay on the original volumes while Cloudmin copies the snapshots.

Freezing filesystems does not guarantee consistent application or database data. Use any additional backup preparation your applications require.

Shut down, back up, then restart requests a clean shutdown before copying the disks. A machine that was running is restarted after copying, before archive compression and transfer. Cloudmin fails the backup if it cannot shut down cleanly; it does not force the power off. A machine with both file and LVM disks requires this method.

Stopped machines stay stopped with either choice. For live UEFI backups, the firmware variables must remain unchanged during the disk snapshot and firmware copy. If they change, the backup fails; retry or choose clean shutdown.

After cancellation or failure, Cloudmin tries to restore the source state and clean up temporary snapshots. If cleanup fails, the job reports it and blocks conflicting disk operations until recovery finishes.
