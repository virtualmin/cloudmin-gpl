Clone Virtual Machine

Cloning makes independent copies of a virtual machine's writable disks on this host. It requires host administrator access and active file, LVM or LVM-thin storage pools. The host needs libguestfs, its Perl bindings and bsdtar. The guest must contain exactly one Linux installation that libguestfs can inspect.

Prepare a new guest identity also requires enabled cloud-init, one network interface and YAML::XS on the host. Before the first boot, an isolated libguestfs worker clears the copied machine ID, SSH host keys, DHCP leases and cloud-init state. New cloud-init data supplies the hostname, selected administrator credentials and network settings. Other application accounts and data remain in the copy.

Keep guest settings and leave stopped preserves guest configuration. Cloudmin still resets the copied host ID and license credentials for supported software. Confirm this choice, then resolve duplicate hostnames, static addresses, keys, credentials and application identities before starting the copy. Automatic startup is disabled.

Templates supply access, network and boot defaults. They do not reinstall software or run provisioning scripts. A template's fully qualified hostname requirement still applies. Plans can change CPU and memory allocations and grow the first disk; disks cannot shrink.

A running source needs guest-agent preparation with a temporary snapshot, or a clean shutdown followed by copying and restart. A source with both file and LVM disks must be shut down for cloning. Filesystem freezing does not replace database-specific backup procedures.

UEFI variables can be copied only while the source is stopped. Running guests default to fresh variables unless you select a clean shutdown. Fresh variables do not preserve the source's firmware boot entries.

Review application settings that use the source hostname or IP address before using the clone. Preparing a new identity does not update every application's configuration.

Both clone modes reset copied license credentials for supported software without changing the source's license. The installed packages and repository channels remain. Supply a separate license or switch to a free edition where available; licensed repository updates may fail until then.

File pools and standard LVM pools need room for the full disk capacities. Thin pools allocate space as data is copied. A running source also needs room for temporary snapshots. Both clone modes need temporary storage on the host for writable disk copies. When copying an LVM disk, free-space checks use its full capacity even if the copy is sparse.

Cancellation and recovery restore the source before releasing its reservation. If cleanup fails, use Active Jobs to retry recovery. Do not remove temporary snapshot files or logical volumes manually.
