Clone Virtual Machine

Cloning creates independent disks for another machine on this host. It requires an inspectable Linux guest and enough storage for the copies.

Preparing a new identity requires cloud-init and one network interface. Cloudmin replaces the machine ID, SSH host keys, hostname, login and network settings. Application data and other accounts remain; review applications that depend on the old hostname or address.

Keeping guest settings leaves the clone stopped. Resolve duplicate addresses, hostnames and credentials before starting it. Both modes reset copied license credentials for supported software; each copy needs its own license where required.

A running source needs a responding guest agent or a clean shutdown. Mixed file and LVM disks require shutdown. Guest-agent preparation provides filesystem consistency, not necessarily database consistency. Copying UEFI variables also requires shutdown; fresh variables omit custom boot entries.

Cloning a software TPM 2.0 guest requires shutdown and preserves its TPM state and UEFI variables. Encrypted or custom TPM storage is not supported. Keep a recovery key for encrypted disks in case changed hardware or guest settings prevent automatic unlocking.

Allow space for full disk copies, temporary work and live snapshots. If cleanup fails, use Active Jobs to recover before further disk operations. Do not delete snapshot files manually.
