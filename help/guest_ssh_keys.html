SSH Keys

Manage an existing account's SSH keys under Edit Virtual Machine > Access > SSH Keys. The virtual machine must be running, and its guest agent must support SSH key commands.

Accounts created with only a password can receive keys later. Adding a key does not change SSH login settings. The account and SSH server must allow key login before the key can be used.

On SELinux guests, the virt_qemu_ga_manage_ssh setting lets the agent manage keys. Cloudmin enables it, when available, during setup of virtual machines created from cloud images and prepared clones. If access is denied just after creation, wait for setup to finish and click Show Keys again. If access remains denied, check the account's file permissions. On SELinux guests with this setting, run setsebool -P virt_qemu_ga_manage_ssh on as root inside the virtual machine.

Select an account to view its keys. With read-only access, or if account lookup fails, the menu offers the account chosen during creation and root. Suggested accounts are not checked for SSH access. Click a key's fingerprint to see its full line, including any authorized_keys options.

Adding or removing a key leaves other entries and open sessions unchanged. Removal deletes the selected entry. If the same key is authorized elsewhere, it can still be used. Cloudmin's own login key cannot be removed here.
