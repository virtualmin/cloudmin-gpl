Image Manager
The Images tab lists downloaded images and imports in progress. Use the checkboxes, Select all and Invert selection to manage several images at once. Delete Selected Images asks for confirmation, cancels active downloads, and removes completed images only when they are not used by a virtual machine or another volume. It never deletes the original file supplied for a host-file import.

In Add Images, choose the storage pool and image source. Select the operating systems to download and click Download Selected Images. Use the list's filter to find a distribution or release. The catalogue is filtered for this host's CPU architecture; for example, Arch Linux is listed only on x86-64 hosts.

Official cloud images are published by the Linux distributions and downloaded from their official servers or mirrors over HTTPS. Cloudmin verifies the HTTPS certificate and checks each downloaded file against the publisher's checksum before import. Open Image Catalogue, then click an image name to inspect its download URL, checksum URL and publisher's information page. Custom entries use URLs supplied by an administrator.

Wait for the download or import to finish, then return to Image Manager. Expand an image name in the table to see its storage location or any error. The Checksum column shows Passed when the downloaded file matched its expected checksum, or Not verified when no successful check is recorded.

You can also download a direct HTTPS URL, upload a file, or copy a file already on this host. These sources accept standalone QCOW2 or raw disk images and installer ISOs. Open Advanced options to select the raw or ISO format and optionally enter a SHA-256 checksum. ISO imports verify supplied checksums and enforce transfer limits but skip disk inspection. The original file is not changed.

Host files are read without root privileges, so the file and its parent directories must allow that access. Files in protected home, Webmin and libvirt directories are unavailable to this reader. Upload a private image instead.

Image imports are limited by available space in temporary storage and the selected storage pool. To set an additional file-size limit in GiB, open Module Configuration and change Maximum image file size in GiB. This limits the image file, not the virtual disk capacity inside it.

The Image Catalogue tab shows images for the host's architecture by default. Disable Show only the host architecture in the image catalogue? in Module Configuration to see all architectures. The Source column identifies Bundled and Custom entries. Download size shows the estimated file size. Choose which columns appear under Module Configuration, Image catalogue columns. The Image column is always shown. Image choices are grouped by distribution, with newer releases first. A compact badge in Add Images shows the estimated download size and support date, when known. Hover over the date for support details. Custom entries are marked; the host architecture is not repeated on each row. Support dates cover the vendor or community maintenance included with a release, including Debian LTS. Optional extended-support subscriptions are not included. Release and end-of-life dates are shown when supplied. The Checksum column shows whether a checksum file is available; verification happens during import. The Download column has separate buttons for the image and its checksum file, when available. These links open the source files in your browser; use Add Images to import an image into Cloudmin storage.

Click an image name to view its details or edit a custom entry. Choose Add custom image to add an entry with an image URL, checksum file URL, and checksum algorithm. Both URLs must use HTTPS. The checksum file must identify the image filename, or contain a single checksum for that image.

Select entries to enable or disable them in Add Images. Custom entries can also be deleted. The custom catalogue is stored in the module configuration and survives module updates. These controls do not change downloaded images or imports already in progress.

Cloudmin verifies checksums but does not yet verify digital signatures. Failed imports are not added to the library as ready images. Directory, filesystem and NFS pools are supported for image imports.

This page adds images to storage. It does not create a virtual machine.

After correcting an import failure, return to the form and submit it again. Cloudmin retries failed imports after cleanup, keeping successful images in the same batch. If a partial import needs cleanup, remove that failed import before retrying. The previous attempt stays in history.
