Create Virtual Machine

Enter a virtual machine name, choose a template and plan, and supply the password or SSH keys required by the login method.

The template supplies the image, network, login and software settings. The plan supplies CPU, memory and disk size. The summary below the selectors shows the current settings. Open a section below it to change them.

The guest hostname defaults to the virtual machine name. You can enter a different hostname in the separate hostname field. Templates can require a fully qualified hostname, such as host.example.com.

Creation makes a separate writable disk: QCOW2 in a file pool, or a raw logical volume in an LVM or LVM-thin pool. The source image remains available for reuse.

If a catalogue image is not already available, Cloudmin downloads it when you click Create Virtual Machine. Selecting an image or saving a template does not download it. Cloudmin shows download progress and verifies the image before creating the guest's disks. It saves the source image in the selected file pool, where it remains available in Image Manager. Later creations reuse a matching downloaded image, including one in another pool. An LVM destination requires an active file pool for the source image.

A failed download stops creation before guest resources are allocated. Cancelling creation leaves its shared image download running for other requests. To cancel that download too, use Image Manager. Cached images are not refreshed automatically when the publisher replaces a file at the same URL.

For Installer ISO, select a catalogue ISO or import your own in Image Manager. Cloudmin creates an empty system disk, mounts the ISO in a read-only CD/DVD drive and boots from it first. Open Remote Access and select Graphical console to install the operating system, create accounts and configure networking. Cloud-init and managed SSH keys are not used. Cloudmin does not inspect ISO contents, so choose an ISO that supports the host's CPU architecture and the selected firmware. After installation, eject the ISO in Edit Virtual Machine or select the system disk as the first boot device.

Account, hostname and IP-address settings apply to Cloud image creation. The network or bridge selection and MAC address apply to both sources.

On a new installation, the form selects Default Template and Default Plan. Choose other saved presets or adjust the fields below. Edit the defaults under System Settings → Machine Templates and Resource Plans.

Default Plan starts with 2 CPUs, 2 GiB of memory and a 20 GiB disk. On a one-CPU host, the unedited Default Plan uses 1 CPU. Default Template selects Rocky Linux 10 for the host architecture, the cloudmin account, password authentication, DHCP, automatic firmware and both startup options. It installs no extra software.

Module Configuration → Virtual machine creation controls the optional virtual machine description field, template descriptions, automatic password generation and managed SSH keys. Template descriptions are hidden by default. Use Show template description? to display them below the selector, either always or only when they differ from the template name.

When Generate an initial password? is enabled, opening a new form fills the password field with a random password. You can see, copy or replace it before creating the virtual machine. When disabled, the field starts empty and hides what you type.

Under Image and storage, choose the installation source, the image and the storage pool. Under Resources, set CPU, memory and disk size. Boot options controls firmware, whether to start the virtual machine after creation, and whether to start it when the host boots.

Under Access, choose the Linux username and login method: SSH keys, Password, or SSH keys and password. The matching password and key fields appear in New virtual machine details.

To set an initial root password, enter root as the username and select Password. Other users can run commands with sudo. Password authentication enables both console and SSH login. The image must support cloud-init and match the host CPU architecture. Cloudmin checks catalogue metadata automatically. Custom images without this metadata are inspected read-only before creation; they require libguestfs, its Perl bindings, and YAML::XS on the host. Images with unknown or incompatible settings cannot be used.

Under Network, choose a libvirt network or an existing host bridge. Automatic addressing uses DHCP. For static addressing, enter IPv4 and/or IPv6 addresses with prefix lengths, gateways and DNS servers. Cloudmin adds direct routes to gateways, including for /32 IPv4 and /128 IPv6 addresses. Set the MAC address here and the guest hostname in New virtual machine details.

Software accepts package names, a preparation script and a final setup script. After cloud-init finishes, Cloudmin runs the preparation script, installs the selected software, then runs the final setup script. Scripts run as root inside the guest, using /bin/sh -e with no interactive input. They receive CLOUDMIN_VM_UUID, CLOUDMIN_HOSTNAME and CLOUDMIN_GUEST_USER. Packages use the guest's configured repositories and can be skipped by leaving the package list empty. Each script offers None, File on host or Enter script. A host file is read when the job is submitted; its contents run inside the guest. These settings can override the selected template. Use the field help for limits and execution details. Do not include reusable secrets. Guest software setup requires a cloud image with systemd, Start after creation and managed virtual machine SSH keys.

The sections below the details, from Image and storage to Boot options, start collapsed by default. Module Configuration controls which start open. Selecting a template fills in its settings without opening or closing sections. Editing a field keeps the selected template and plan and updates the summary.

Click Create Virtual Machine to validate the settings and start a background job. If a setting needs correcting, Webmin shows an error with a return link. Closing the progress page does not cancel creation. Use Active Jobs on Host Overview to return to progress, cancel an unfinished creation or retry cleanup. Completed actions appear in the Host Action Log. Cancellation takes effect between creation steps; a disk copy may need to finish first.

When the job reaches software setup, the virtual machine is available for editing, snapshots, power controls and deletion. Cancelling the job stops software setup and keeps the virtual machine and its disks. It does not undo software already installed. If Cloudmin cannot reach the guest to stop setup, it reports an error; you can still stop the virtual machine using its power controls.

A setup failure also keeps the virtual machine and its disks. For a failed script or software installation, check /var/lib/cloudmin-install/install.log inside the guest. Errors during initial guest setup may occur before this log exists; check cloud-init's status and logs for those errors.

Reopening progress shows the saved setup status. Failed or interrupted scripts and installations are never repeated automatically. The full software setup sequence has a two-hour time limit.

When you return to Cloudmin, it checks interrupted jobs against their saved records and libvirt. It keeps successfully created virtual machines and attempts to remove resources from unfinished creations. Cleanup failures name the problem and provide Retry cleanup. After correcting a creation failure, return to the form and submit it again. Cloudmin starts a new attempt once cleanup has finished. The previous failure stays in job history. Repeated clicks return to the same attempt. If software setup failed, use the existing virtual machine to resolve it instead of creating another one.

The details page automatically refreshes power state, reported IP addresses, guest-agent response and SSH availability on port 22. These are separate checks: a running virtual machine or responding SSH service does not mean cloud-init has finished. Creation supports cloud images and installer ISOs, with guest disks in active directory, filesystem, NFS, LVM or LVM-thin pools. Images and UEFI variables need a file pool. After creation, use Edit Virtual Machine to add disks or network interfaces. Live changes require support from libvirt and the guest.
