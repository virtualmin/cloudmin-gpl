Erstellen Sie ein EC2-Image
Auf dieser Seite können Sie ein laufendes virtuelles EC2-System in einem Image (auch als AMI bezeichnet) erstellen, das dann zum Erstellen neuer EC2-Instanzen verwendet werden kann. Diese Bilder ähneln denen, die Cloudmin zum Erstellen von Xen- und VServer-Systemen verwendet, werden jedoch im S3-Dienst von Amazon und nicht auf Ihrem Cloudmin-Mastersystem gespeichert.

Um ein Bild zu erstellen, müssen Sie die folgenden Felder ausfüllen:

S3 Eimer für Bild
Ein Bucket ist wie ein Verzeichnis in Ihrem S3-Speicher. In dieses Feld sollten Sie einen Kurznamen wie centos-virtualmin-custom eingeben , der beim Erstellen des Bildes erstellt wird. Jeder Bucket kann nur von einem einzelnen EC2-Image verwendet werden.
Speichern Sie unter S3-Konto
Wenn Sie mehr als ein EC2-Konto haben, wählen Sie in diesem Menü das Konto aus, in dem das neue Bild gespeichert und gespeichert werden soll.
Größe des Bilddateisystems
Wenn ein System aus Ihrem neuen Image erstellt wird, hat sein Root-Dateisystem die hier eingegebene Größe - und kann nicht erweitert werden. Die Größe ist ein Kompromiss zwischen dem Speicherplatz, den Sie zum Hosten von Domains in den virtuellen Systemen benötigen, und dem Betrag, den Amazon für das Speichern des Images in S3 berechnet.
Bild öffentlich zugänglich machen?
Wenn Ja ausgewählt ist, kann das neue Bild von jedem verwendet werden, der Ihre EC2-Kontonummer kennt. Dies ist nicht ratsam, wenn Sie ein Image erstellen, das kommerzielle Software wie Virtualmin Pro enthält.
Wenn Sie auf die Schaltfläche Bild erstellen klicken, beginnt der Vorgang zum Erstellen eines Bildes aus dem System. Es wird während des Imaging nicht heruntergefahren, es wird jedoch empfohlen, die Verwendung des Quellsystems zu minimieren, um die Änderung von Dateien in einem inkonsistenten Zustand zu reduzieren.
