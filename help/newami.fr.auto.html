Créer une image EC2
Cette page peut être utilisée pour créer un système virtuel EC2 en cours d'exécution dans une image (également appelée AMI), qui peut ensuite être utilisée pour créer de nouvelles instances EC2. Ces images sont similaires à celles utilisées par Cloudmin pour créer des systèmes Xen et VServer, mais sont stockées sur le service S3 d'Amazon, plutôt que sur votre système maître Cloudmin.

Pour créer une image, vous devez remplir les champs suivants:

Godet S3 pour l'image
Un compartiment est comme un répertoire dans votre stockage S3. Dans ce champ, vous devez entrer un nom court comme centos-virtualmin-custom , qui sera créé lors de la création de l'image. Chaque compartiment ne peut être utilisé que par une seule image EC2.
Enregistrer sous le compte S3
Si vous avez plusieurs comptes EC2, sélectionnez le compte qui sera utilisé pour stocker et posséder la nouvelle image dans ce menu.
Taille du système de fichiers image
Lorsqu'un système est créé à partir de votre nouvelle image, son système de fichiers racine sera de la taille entrée ici - et ne peut pas être développé. La taille est un compromis entre la quantité d'espace disque dont vous aurez besoin pour héberger des domaines dans les systèmes virtuels et la quantité qui vous est facturée par Amazon pour stocker l'image dans S3.
Rendre l'image accessible au public?
Si Oui est sélectionné, la nouvelle image sera utilisable par toute personne connaissant votre numéro de compte EC2. Ce n'est pas conseillé si vous créez une image contenant un logiciel commercial comme Virtualmin Pro.
Lorsque vous cliquez sur le bouton Créer une image , le processus de création d'une image à partir du système démarre. Il ne sera pas arrêté pendant la création d'image, mais il est recommandé de minimiser l'utilisation du système source pour réduire la modification des fichiers dans un état incohérent.
