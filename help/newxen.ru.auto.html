Создать новую систему Xen
Эта страница позволяет вам создать новую виртуальную систему, работающую внутри экземпляра Xen. Поскольку Cloudmin всегда создает новые системы Xen из изображений, вы должны загрузить хотя бы одно изображение с помощью страницы «Новые образы системы», прежде чем можно будет создать экземпляр.

Поля в этой форме, которые необходимо заполнить для создания экземпляра Xen:

Имя хоста системы
Это должно быть имя нового экземпляра Xen, который не должен содержать имя домена. Подходящие имена экземпляров похожи на centos1 или xen-foocorp . Окончательное имя хоста экземпляра будет иметь добавленное доменное имя DNS для хост-системы.
Описание системы
Краткое понятное человеку описание этой новой виртуальной системы, такой как Webserver для Foo Corp.
Исходный образ системы
В этом меню вы должны выбрать образ операционной системы Xen для запуска новой системы. Cloudmin предоставляет два типа образов - базовые операционные системы и полные стеки с Virtualmin. В большинстве случаев вам захочется выбрать последнее.
Режим рут-входа
Это поле позволяет вам установить начальный пароль для нового экземпляра Xen. Обычно вы выбираете «Использовать пароль» и вводите пароль в смежное текстовое поле, которое затем может быть передано тому, кто будет управлять сервером. В качестве альтернативы, если у вас есть какие-либо SSH-ключи, зарегистрированные в Cloudmin, вы можете выбрать «Использовать SSH-ключ» и выбрать ключ в меню рядом с ним. После того, как экземпляр создан, он будет настроен для входа без пароля с использованием этого ключа.
Разрешить создание доменов Virtualmin?
Этот параметр определяет, могут ли новые создаваемые системы добавлять к нему домены Virtualmin. Обычно вы хотите оставить этот набор на Да .
Обновить пакеты Virtualmin?
Если для этого параметра установлено значение Да (как по умолчанию), и вы создаете систему из образа, содержащего Virtualmin Pro, все пакеты, используемые Virtualmin, будут обновлены до последних доступных версий после завершения создания.
Xen хостинг
В этом меню вы должны выбрать физическую систему, в которой вы хотите создать экземпляр Xen.
IP-адрес для экземпляра Xen
Каждой новой системе Xen присваивается частный IP-адрес, который может быть либо назначен автоматически из диапазона, определенного для хост-системы, либо введен вручную, выбрав опцию «Адрес» .
Если мастер Cloudmin запускает DNS-сервер (настоятельно рекомендуется), в зону DNS, выбранную для хост-системы Xen, будет добавлена запись для полного имени хоста и IP-адреса экземпляра Xen.
Память, выделенная для экземпляра
Экземпляры Xen имеют фиксированную верхнюю границу объема памяти, которую они могут использовать, что контролируется этой опцией. 256 - минимум для системы веб-хостинга с Virtualmin, но рекомендуется 512.
Например, размер файла подкачки
По умолчанию Cloudmin создает экземпляры Xen с обычной выделенной памятью, но без пространства подкачки. Однако вы можете выбрать здесь вторую радиокнопку и ввести объем подкачки (виртуальной) памяти, выделяемой в МБ, что позволит процессам в экземпляре использовать больше, чем выделенная ОЗУ, за счет производительности. Поскольку пространство подкачки хранится в файле на хост-системе того же размера, рекомендуется ограничить его двойным объемом обычной памяти.
Дисковое пространство, выделенное для экземпляра
В отличие от некоторых других типов виртуальных машин, Xen хранит файловую систему каждого экземпляра в одном файле на хосте, который представляет собой образ диска в формате EXT3. Таким образом, размер файловой системы в экземпляре ограничен размером образа диска.
По умолчанию размер файла диска зависит от выбранного образа системы. Все образы, содержащие полный стек Virtualmin, составляют 2 ГБ, а образы только с базовой ОС - 1 ГБ. Поскольку этого может быть недостаточно для системы, в которой будут размещаться несколько веб-сайтов, вы можете ввести больший размер в МБ с помощью этой опции, и образ диска будет увеличен до этого размера в процессе создания экземпляра.
При нажатии кнопки «Создать» Cloudmin запускает процесс установки Xen. Сообщения о состоянии будут отображаться по мере выполнения каждого шага. Общее время зависит от размера образа, скорости хост-системы и скорости сети между хостом и мастером Cloudmin, но в среднем около пяти минут.
