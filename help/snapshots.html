Snapshots

Snapshots preserve disks and hardware settings for a later rollback. They do not save RAM or firmware variables and are not a substitute for backups on separate storage.

A running machine needs guest-agent preparation or a clean shutdown for a consistent snapshot. Databases may need additional preparation. Without either, restoring is like recovering from sudden power loss. Cloudmin does not force shutdown; if creation fails after shutdown, check the error before restarting.

Restoring discards changes since the selected snapshot and restores its hardware settings. Starting afterward boots the guest afresh. Deleting a snapshot removes that restore point while keeping the current machine state.

Snapshots need private file or LVM disks; mixed storage and external device state such as TPMs or passthrough devices are unsupported. Monitor snapshot space, including thin-pool metadata. LVM restore also needs temporary space for the largest disk's full capacity. Remove LVM snapshots before deleting the machine.

Up to 20 snapshots are allowed per machine. Snapshots made with other tools must be removed with those tools before Cloudmin can manage snapshots. A restore point with child snapshots may require deleting the children first.

If an operation partly fails, recover it through Active Jobs before further changes. Do not delete snapshot files manually. If recovery cannot thaw guest filesystems, stop the machine and retry recovery.
