Snapshots

A snapshot saves a virtual machine's writable disks and hardware configuration at a point in time. It stays on the same storage as the virtual machine and depends on that storage. Keep separate backups for recovery from disk failure.

For a running virtual machine, Cloudmin asks libvirt to prepare the guest filesystems using QEMU Guest Agent, take the snapshot, and resume writes. The agent must be installed and responding inside the guest. Cloudmin never silently retries without preparation. Applications such as databases may also need their own hooks to prepare their data.

If the agent is unavailable, Shut down before taking snapshot is enabled by default. Cloudmin requests a clean shutdown, takes the snapshot, and starts the virtual machine again. If the agent responds before the operation starts, the virtual machine stays running.

Cloudmin never forces shutdown. If shutdown does not finish within two minutes, the snapshot is not taken. If snapshot creation fails after shutdown, review the error before starting the virtual machine.

Disabling the shutdown option requests a live snapshot without preparing the guest filesystems. Restoring it may require filesystem or application recovery, as after an unexpected power loss. Taking the snapshot leaves the virtual machine running.

A stopped virtual machine needs no guest agent. Its disks are clean only if it was shut down normally.

Snapshots do not save RAM, active connections, firmware variables, or external services. Guests with TPMs, shared folders, persistent memory, or passthrough devices are not supported. Writable disks must be private raw or QCOW2 files, or managed LVM disks. A snapshot cannot mix file and LVM disks.

LVM snapshots keep writes on the original disks. Cloudmin briefly pauses a running guest while creating them. Live LVM snapshots require direct I/O or synchronous disk caching; disks created by Cloudmin use direct I/O. Standard LVM reserves space for a full disk's changes, while thin snapshots share their pool. Monitor both data and metadata usage in thin pools.

Restoring an LVM snapshot copies the saved data back while the virtual machine is stopped. The host needs temporary space under /var/tmp for the largest disk's full capacity plus 256 MiB. Remove LVM snapshots before deleting the virtual machine.

Cloudmin attempts snapshot operations using the installed libvirt. If an operation fails, its progress page shows the error returned by libvirt at the affected step. Some host configurations allow creation but reject deletion or restore. If an operation leaves unfinished changes, use its recovery action in Active Jobs. Up to 20 snapshots can be retained per virtual machine; delete unneeded points to keep disk chains manageable.

Each snapshot has Restore and Delete actions, both in its virtual machine history and on All Snapshots. The confirmation page identifies the snapshot to restore and requests a clean shutdown if the virtual machine is running. Restore discards changes made since the selected snapshot.

Start the virtual machine after restoring is enabled by default for snapshots taken while running and disabled for snapshots taken while stopped. You can change this choice. Starting boots from the restored disks; it does not resume the earlier running session. Other saved snapshots remain available.

Deleting a snapshot removes that restore point and merges disk data as needed; it does not restore or delete the current virtual machine.

The activity feed lists snapshots in time order. Based on links show their parent snapshots, and Parent of current state marks the snapshot on which the current virtual machine state is based. The virtual machine continues to change after that point. Snapshots made with other tools are displayed but must be managed with those tools. Cloudmin disables snapshot creation, restore and deletion for that virtual machine until snapshots managed elsewhere have been removed with their original tool.

If the current restore point has child snapshots, delete those children first. Its Delete action stays disabled until libvirt can remove it safely.

Snapshot operations appear in Active Jobs and survive browser disconnection. If an operation needs recovery, use the job's recovery action before making further virtual machine changes. Do not manually remove snapshot disk files.

If the guest agent stops responding during preparation and recovery cannot resume filesystem writes, stop the virtual machine and run recovery again. The confirmed Force power off action remains available for this case.

After correcting a failed operation, return to its form and submit it again. Cloudmin starts a new attempt once recovery has finished. If the operation partly completed, use Active Jobs to finish recovery first. Previous attempts remain in job history.
