Storage

Pools make directories, NFS exports and LVM volume groups available for virtual machine disks. Registering existing storage preserves its contents. File pools are also needed for imported images, installation media and UEFI variables.

Virtual capacity is the disk size seen by the guest; allocated space is what it currently uses on the host. Pools sharing a filesystem share its free space. Pool capacity is not a quota.

Standard LVM reserves the full disk size. Thin pools allocate space as data is written, so monitor both data and metadata usage and extend them before they fill. Cloudmin blocks new allocations at 95% data or 90% metadata usage, but running guests can still fill a pool.

Shut down before growing an LVM disk. Disk copying and preparation also need local temporary space, sometimes the full disk capacity.

NFS needs an existing export writable by libvirt and the host's QEMU user. Choose an empty local mount directory. Starting the pool mounts the export. Stopping it unmounts it. On SELinux hosts, registering or starting an NFS pool allows virtual machines to access NFS. This setting survives reboots.

Cloudmin checks only local guests, so do not attach the same writable disk to guests on different hosts. NFS volumes cannot be deleted here.

Stopping a pool makes it unavailable for new operations. Stopping an LVM pool deactivates its logical volumes, so stop guests and release any mounts or swap using them first. Unregistering removes the Cloudmin registration while keeping files and volumes intact.

Volume deletion permanently removes unused disks. Manage attached disks through their machine and imported images through Image Manager. Snapshots, shared backing files and pending jobs can prevent deletion.
