URL de destino de respaldo
Los destinos de copia de seguridad se deben ingresar en el formato utilizado por el comando virtualmin backup-domain API. Por ejemplo :
  • Un archivo local, como /backup/yourdomain.com.tgz

  • Un destino FTP, como ftp://login:pass\@server/backup/domain.com.tgz

  • Un destino SSH, como ssh://login:pass\@server/backup/domain.com.tgz

  • Un depósito de S3, como s3://accesskey:secretkey@bucket/domain.com.tgz

  • Un contenedor Rackspace, como rs://user:apikey@container/domain.com.tgz

  • Un depósito de Google Cloud Storage, como gcs://bucket/domain.com.tgz

  • Una carpeta de Dropbox, como dropbox://folder/domain.com.tgz
Se supondrá que cualquier destino que termine con tar.gz o zip será un solo archivo, que contendrá todos los dominios seleccionados. Cualquier otra cosa será tratada como un directorio, que recibirá un archivo por dominio.

Para las copias de seguridad de Dropbox y GCS, cada sistema Virtualmin ya debe tener una cuenta con el proveedor de almacenamiento configurado.

Puede usar las etiquetas ${HOST} y ${IP} en los destinos de respaldo, que serán reemplazados por el nombre de host del sistema de origen y la dirección IP respectivamente para cada sistema. Esto permite que diferentes sistemas realicen copias de seguridad en diferentes directorios finales.
