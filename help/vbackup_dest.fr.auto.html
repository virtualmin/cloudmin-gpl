URL de destination de sauvegarde
Les destinations de sauvegarde doivent être saisies au format utilisé par la commande API de virtualmin backup-domain . Par exemple :
  • Un fichier local, comme /backup/yourdomain.com.tgz

  • Une destination FTP, comme ftp://login:pass\@server/backup/domain.com.tgz

  • Une destination SSH, comme ssh://login:pass\@server/backup/domain.com.tgz

  • Un s3://accesskey:secretkey@bucket/domain.com.tgz S3, comme s3://accesskey:secretkey@bucket/domain.com.tgz

  • Un conteneur Rackspace, comme rs://user:apikey@container/domain.com.tgz

  • Un gcs://bucket/domain.com.tgz Google Cloud Storage, comme gcs://bucket/domain.com.tgz

  • Un dossier Dropbox, comme dropbox://folder/domain.com.tgz
Toute destination se tar.gz par tar.gz ou zip sera supposée être un seul fichier, qui contiendra tous les domaines sélectionnés. Tout le reste sera traité comme un répertoire, qui recevra un fichier par domaine.

Pour les sauvegardes Dropbox et GCS, chaque système Virtualmin doit déjà avoir un compte avec le fournisseur de stockage configuré.

Vous pouvez utiliser les balises ${HOST} et ${IP} dans les destinations de sauvegarde, qui seront remplacées respectivement par le nom d'hôte et l'adresse IP du système source pour chaque système. Cela permet à différents systèmes de sauvegarder dans différents répertoires finaux.
