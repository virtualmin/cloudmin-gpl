URL di destinazione del backup
Le destinazioni di backup devono essere immesse nel formato utilizzato dal comando API del virtualmin backup-domain . Per esempio :
  • Un file locale, come /backup/yourdomain.com.tgz

  • Una destinazione FTP, come ftp://login:pass\@server/backup/domain.com.tgz

  • Una destinazione SSH, come ssh://login:pass\@server/backup/domain.com.tgz

  • Un bucket S3, come s3://accesskey:secretkey@bucket/domain.com.tgz

  • Un contenitore Rackspace, come rs://user:apikey@container/domain.com.tgz

  • Un bucket di Google Cloud Storage, come gcs://bucket/domain.com.tgz

  • Una cartella Dropbox, come dropbox://folder/domain.com.tgz
Qualsiasi destinazione che termina con tar.gz o zip verrà considerata come un singolo file, che conterrà tutti i domini selezionati. Qualsiasi altra cosa verrà trattata come una directory, che riceverà un file per dominio.

Per i backup Dropbox e GCS, ogni sistema Virtualmin deve già avere un account con il provider di archiviazione configurato.

È possibile utilizzare i tag ${HOST} e ${IP} nelle destinazioni di backup, che verranno sostituiti rispettivamente dal nome host e dall'indirizzo IP del sistema di origine per ciascun sistema. Ciò consente a diversi sistemi di eseguire il backup in diverse directory finali.
