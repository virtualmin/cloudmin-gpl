Zapasowe docelowe adresy URL
Miejsca docelowe kopii zapasowych należy wprowadzić w formacie używanym przez komendę interfejsu API virtualmin backup-domain . Na przykład :
  • Plik lokalny, taki jak /backup/yourdomain.com.tgz

  • Miejsce docelowe FTP, takie jak ftp://login:pass\@server/backup/domain.com.tgz

  • Miejsce docelowe SSH, takie jak ssh://login:pass\@server/backup/domain.com.tgz

  • Wiadro S3, takie jak s3://accesskey:secretkey@bucket/domain.com.tgz

  • Kontener Rackspace, taki jak rs://user:apikey@container/domain.com.tgz

  • Wiadro Google Cloud Storage, takie jak gcs://bucket/domain.com.tgz

  • Folder Dropbox, taki jak dropbox://folder/domain.com.tgz
Każde miejsce docelowe, które kończy się na tar.gz lub zip będzie traktowane jako pojedynczy plik, który będzie zawierał wszystkie wybrane domeny. Wszystko inne będzie traktowane jak katalog, który otrzyma jeden plik na domenę.

W przypadku kopii zapasowych Dropbox i GCS każdy system Virtualmin musi mieć skonfigurowane konto u dostawcy pamięci masowej.

Możesz użyć tagów ${HOST} i ${IP} w miejscach docelowych kopii zapasowych, które zostaną zastąpione odpowiednio przez nazwę hosta systemu źródłowego i adres IP odpowiednio dla każdego systemu. Umożliwia to tworzenie kopii zapasowych różnych systemów w różnych końcowych katalogach.
