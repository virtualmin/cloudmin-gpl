URLs de destino de backup
Os destinos de backup devem ser inseridos no formato usado pelo comando da API virtualmin backup-domain . Por exemplo :
  • Um arquivo local, como /backup/yourdomain.com.tgz

  • Um destino de FTP, como ftp://login:pass\@server/backup/domain.com.tgz

  • Um destino SSH, como ssh://login:pass\@server/backup/domain.com.tgz

  • Um bucket S3, como s3://accesskey:secretkey@bucket/domain.com.tgz

  • Um contêiner Rackspace, como rs://user:apikey@container/domain.com.tgz

  • Um bucket do Google Cloud Storage, como gcs://bucket/domain.com.tgz

  • Uma pasta do Dropbox, como dropbox://folder/domain.com.tgz
Qualquer destino que termine com tar.gz ou zip será considerado um único arquivo, que conterá todos os domínios selecionados. Qualquer outra coisa será tratada como um diretório, que receberá um arquivo por domínio.

Para backups do Dropbox e GCS, cada sistema Virtualmin já deve ter uma conta com o provedor de armazenamento configurado.

Você pode usar as tags ${HOST} e ${IP} nos destinos de backup, que serão substituídos pelo nome do host e pelo endereço IP do sistema de origem, respectivamente, para cada sistema. Isso permite que diferentes sistemas façam backup em diferentes diretórios finais.
