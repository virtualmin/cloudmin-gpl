Резервные URL назначения
Назначения резервного копирования должны быть введены в формате, используемом командой virtualmin backup-domain API. Например :
  • Локальный файл, например /backup/yourdomain.com.tgz

  • FTP-адрес, такой как ftp://login:pass\@server/backup/domain.com.tgz

  • Назначение SSH, например, ssh://login:pass\@server/backup/domain.com.tgz

  • Ведро S3, например s3://accesskey:secretkey@bucket/domain.com.tgz

  • Контейнер Rackspace, например rs://user:apikey@container/domain.com.tgz

  • Ведро Google Cloud Storage, например, gcs://bucket/domain.com.tgz

  • Папка Dropbox, например dropbox://folder/domain.com.tgz
Предполагается, что любое место назначения, заканчивающееся tar.gz или zip будет одним файлом, который будет содержать все выбранные домены. Все остальное будет рассматриваться как каталог, который получит один файл на домен.

Для резервных копий Dropbox и GCS каждая система Virtualmin уже должна иметь учетную запись с настроенным поставщиком хранилища.

Вы можете использовать теги ${HOST} и ${IP} в местах назначения резервного копирования, которые будут заменены именем хоста исходной системы и IP-адресом соответственно для каждой системы. Это позволяет различным системам выполнять резервное копирование в разные конечные каталоги.
